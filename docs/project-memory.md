# 项目记忆

项目记忆保存经用户确认的重要事实、约束、偏好和笔记，供同一项目的新聊天
按需回忆。侧栏“项目记忆”可管理内容，聊天消息下的记忆图标可手动整理消息。
记忆默认关闭；自动提取有独立开关，也默认关闭。

## 从消息到记忆

1. 用户开启“聊天记忆”和“自动整理候选记忆”，选择部署已授权的提取模型。
2. 新用户消息与提取任务在同一个数据库事务保存。不会补扫历史，不从助手回答
   自动推定用户事实。严格知识库问答和后台任务不参与提取或长期记忆召回。
3. 现有任务 worker 在后台调用一次模型，最多提出 5 条新增或更新建议。
   输入含新消息、同一会话最多 6 条此前用户消息（仅帮助理解指代），以及当前
   项目相关的最多 8 条有效记忆。旧记忆采用词项匹配选择，不跨项目搜索。
4. 候选必须带新消息中的逐字原文依据。更新只能指向后端提供的记忆索引，
   无法用模型生成的 UUID 指向其他账号或项目。模型不具有删除权限。
5. 页面显示候选内容、原文、整理理由及更新前的内容。用户可编辑后确认或忽略。
   只有确认后才加入召回。原记忆已被编辑、归档或过期时返回 409，不覆盖新版本。

自动提取会将上述文本发送给选定的生成模型，可能产生模型调用费用；本地向量
编码本身不调用云端 embedding API。开启前的消息不回填。

短消息、超过 6000 字符的消息及包含常见凭据标记的消息跳过自动提取。凭据
过滤是保守规则，不保证识别所有敏感数据。原文包含校验也不能证明模型完整
理解了事实，因此人工确认仍是写入门槛。用户当前的明确请求优先于旧记忆。

## 更新、遗忘与持续保留

- 无截止日期的确认记忆持续保留，不因使用频率低而自动删除。
- 可设置“有效至”，按 UTC 日期计算，包含该日期；次日起退出召回。
  模型仅在明确给出期限和期限原文时建议到期日，用户仍需核对。
- 归档立即停止后续召回，恢复后重新参与索引；恢复已过期条目仍须修改到期日。
  归档和过期均不物理删除记录，置顶不能绕过这些条件。
- 待确认建议 7 天后不再显示或允许确认。worker 在其有效期结束 30 天后清理。
  已结束的提取任务记录保留 30 天，待处理任务最多恢复 7 天。
- 每次内容编辑、归档或恢复增加修订号，最多保留最近 30 个版本。
  删除记忆会删除其版本及关联候选；列表包括已过期和已归档条目，均计入配额。
- 普通编辑不能更换来源；确认更新建议时，当前记忆来源变更为新用户消息。
  删除旧来源会删除使用该来源的旧版本，当前记忆保留；删除当前来源会删除
  当前记忆及其全部版本。手动创建、没有消息来源的笔记独立保留。
- 关闭记忆同时关闭自动提取，已有条目和候选仍保留供手动管理。关闭、归档或
  删除影响后续召回，无法撤回已发送给模型的文本或历史回答中出现的内容。

## 召回、索引与上下文

本地 `BAAI/bge-small-zh-v1.5` 生成 512 维向量，复用离线模型缓存。
记忆按 320 字符分段，带标题编码后取均值并归一化，覆盖整条内容；召回仍
保留整条原记忆，不截掉否定条件。PostgreSQL pgvector 储存可重建索引，
查询先限定账号、项目、有效状态、内容修订号和模型指纹，再按余弦相似度排序。
相似度阈值 0.45 是候选门槛，不代表事实置信度。

语义排名与中文双字词/英文词排名采用 RRF 合并，有效置顶条目优先。
每轮最多载入 6 条完整记忆，记忆上下文最多 4000 字符、1600 个估算 token。
估算并非供应商 tokenizer 的精确计数，超预算条目整条跳过。记忆使用元数据
只保留条目 ID、修订号及召回方式，不再复制记忆正文。

索引在现有 task worker 内逐条生成，失败最多尝试两次。内容变化立即废弃旧
向量；模型变化需要点击“重建记忆索引”。查询本地编码最多等待 3 秒，繁忙、
未就绪、失败或指纹不符时回退关键词，测试召回页面展示实际模式和原因。
超时的原生线程未结束前仍占用该 API 进程唯一查询槽，避免不断堆积编码任务。

记忆是补充参考，不是工具授权、系统指令或知识库 `[1]` 引文。事实冲突时
提示模型说明冲突或请求澄清。短期聊天窗口和任务 checkpoint 沿用现有模块；
本功能不增加全会话摘要、记忆图谱、跨项目召回或自主遗忘策略。

## 隔离、并发与成本

知识库仍属于账号，可跨项目复用；记忆按 **账号 + 项目** 隔离。缺省项目
仅表示默认空间，不能读取其他项目。后端验证项目、来源和更新目标的所有权。
WebSocket 使用连接建立时验证的项目，查询、设置、候选处理、历史、索引和
任务重试均受相同边界约束。

- 每条正文最多 1200 字符、标题 80 字符；每项目 100 条、每账号 500 条。
- 同项目规范化空白后的重复正文拒绝保存；候选也进行正文哈希去重。
  语义近似内容由提取提示和用户核对处理，不保证自动消除所有语义重复。
- 每账号滚动 24 小时最多 20 个提取任务，排队或运行中最多 10 个，
  每项目同时最多 20 个待确认候选。失败可手动重试一次，总尝试不超过两次。
- 推理最长 40 秒、一次请求、最多 3000 输出 token，记录供应商返回的 token
  用量；实际费用遵循部署模型供应商的计费。提取与聊天生成的费用分别发生。
- 账号行锁保护配额和短事务；不会在模型网络请求期间持有账号行锁。
- PostgreSQL advisory lock 防止多 worker 同时处理相同任务；任务尝试号、
  设置修订、来源和目标版本再次验证，关闭后重新开启也不能复活旧设置任务。
- 既有 worker 增加一个有限并发循环，不增加数据库、消息队列、模型服务或
  每用户独占进程。过期清理与索引均受现有容器资源上限约束。

## 借鉴范围与部署

独立实现借鉴 Mem0 的事实提取、历史记忆参考、去重、向量检索和到期过滤思路，
不依赖 Mem0 SDK 或云端服务。该项目是记忆基础设施，不是一个基础大模型。
截至本轮研究的 Mem0 main，`add` 是 ADD-only 提取，也提供显式更新/删除 API；
旧版有 ADD/UPDATE/DELETE/NONE 决策。本项目采用需人工确认的新增/更新路径，
不把旧版自动删除行为当成当前默认能力。
参考：<https://github.com/mem0ai/mem0>（研究版本 `c7ee362aff94a369af70f13f2b4f853f6793ff4c`）。

迁移 `0042_memory_lifecycle` 在 `0041_project_memory` 上新增设置、生命周期、
向量列及版本/候选/提取任务表，无需迁移文档或会话。部署前备份数据库；
回退应用可保留新增结构，数据库 downgrade 会删除本轮新增数据。

验证包括记忆单元测试、真实 PostgreSQL 隔离和生命周期测试、FunctionModel
结构化提取、前端核对/代理测试及桌面和手机浏览器检查。数据库测试仅启用
`RUN_TASK_DB_TESTS=1` 于 `_review` 临时数据库，先迁移并 setup 任务 checkpoint。
