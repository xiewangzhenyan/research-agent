# 项目记忆（Mem0）

开启“聊天记忆”后，系统自动从后续用户消息中整理长期有用的事实、偏好、决定
和约束，保存后即可参与后续回答。无需逐条确认。页面提供查看原文、编辑、
归档、删除及版本记录。总开关默认关闭；开启一次即同时启用自动整理和召回。
知识库属于账号，可以跨项目使用；记忆始终按 **账号 + 项目** 隔离。

## 从聊天到自动记忆

1. 用户消息与整理任务在同一 PostgreSQL 事务保存。普通对话采用持久化执行，
   关闭网页不影响已入队的任务。严格知识库问答不参与长期记忆整理和召回。
2. Worker 调用固定版本 `mem0ai==2.0.20` 的 `Memory.add`。Mem0 负责已有事实
   检索、提取提示、单次模型调用、批量向量生成及正文哈希去重。
3. 提取调用通过 PydanticAI 适配已授权的生成模型。项目扩展要求最多 5 条，
   保留范围、否定和数字，并附新消息中的逐字原文；自动校验原文和更新目标。
   近期最多 6 条同会话用户消息、合计最多 3000 字符只帮助理解指代，不作为
   新事实来源。供提取参考的相关旧记忆最多 10 条、2400 个估算 token，整条选取。
4. SDK 整理结果先暂存在本次任务的内存中。Worker 再校验账号、项目、消息、
   设置修订和目标版本，将事实、向量、来源、版本及任务完成状态原子提交。
   没有待用户确认的阶段，也不把助手回答自动推定为用户事实。
5. 已保存条目标注“自动整理”；用户手动修改后标注“手动保存”。可以展开
   原文，也可进入来源会话。当前明确请求优先于旧记忆。

少于 4 字符、超过 6000 字符或包含常见凭据标记的消息跳过整理。过滤及原文
校验不能证明语义判断一定正确，用户可以纠正结果。不补扫开启前的历史。
提取会将上述内容发送给选定的生成模型，产生独立的模型用量；向量生成使用
本地模型，不调用云端 embedding API。

## Mem0 与项目扩展的边界

采用一个 Mem0 引擎，不提供 builtin / mem0 切换开关，也不保留原自研提取器。
项目适配层位于 `backend/app/services/mem0_memory.py`。

- 本版本 Mem0 自动提取为 ADD-only。项目扩展在用户明确纠正同一对象和属性时，
  将新增事实应用为现有条目的新修订，保留旧版本。目标只能来自服务端提供的
  相关记忆索引。模糊冲突不允许任意覆盖；模型不能物理删除记忆。
- SDK 标准构造器会创建独立 SQLite 历史。适配层注入 PostgreSQL 的已授权快照、
  近期会话视图及暂存写入端口，复用现有 `memory_items` / `memory_versions`。
  不创建第二份持久事实库或 SQLite 对话副本，不存在两个数据库独立提交的问题。
- 内部身份固定为服务端生成的 `account:<id>:project:<id|default>`，覆盖提取阶段
  的旧记忆查询和最终召回。前端与模型不能自行指定该身份。
- 适配器依赖已锁定版本的构造字段和存储协议；升级 SDK 必须运行真实 SDK
  合约测试。没有复制或修改安装目录中的 SDK 源文件。
- 禁用 SDK 遥测、营销提示请求和 spaCy 自动下载。没有启用英文实体链接、
  Neo4j 图谱或托管平台专有能力。SDK 的传递依赖会安装 Qdrant 客户端，
  应用不会连接或启动 Qdrant 服务。

## 更新、遗忘和一致性

- 确认存在明确截止日期及期限原文时才设置有效期；按 UTC 日期计算，包含
  当日，次日起停止召回。没有截止日期的记忆持续保留，不按使用频率删除。
- 归档立即退出后续召回；过期和归档均不物理删除。置顶不能绕过有效性条件。
- 每次内容编辑、归档或恢复增加修订号，最多保留最近 30 个版本。
- 删除记忆同时删除其版本和关联旧候选。删除当前来源消息会删除当前记忆；
  删除旧来源只清理引用它的旧版本。无来源的手动笔记独立保留。
- 人工编辑、删除、归档或更改设置会使已排队/正在运行的旧任务失效，避免
  用户刚纠正的信息又被旧结果恢复。新消息可继续触发新的整理。
- 同项目的提取使用 PostgreSQL advisory lock 串行提交。失败任务重试前检查
  是否已有更新消息完成整理；过时任务跳过，不倒写旧事实。
- 整理的模型调用期间不持有账号行锁。提交时检查任务尝试号、设置修订、
  来源内容和目标版本。SDK 暂存阶段没有数据库副作用，失败可安全重试。
- 召回在等待本地编码后再次检查设置和条目修订，丢弃期间被修改、删除或
  归档的条目。已发送给模型的文本和历史回答不因后续删除而撤回。

## 召回、资源与当前边界

本地 `BAAI/bge-small-zh-v1.5` 生成 512 维向量，复用现有模型缓存。完整正文
按 320 字符分段，带标题编码、均值归一化，避免只编码第一段。
PostgreSQL pgvector 按账号、项目、有效状态、内容修订及模型指纹过滤后查询。
Mem0 对这些候选进行语义与关键词融合排序；中文双字词和英文词的 BM25 由
项目存储适配层提供。有效置顶条目优先；关键词命中仍可补充未建好向量的记忆。

每轮最多载入 6 条完整记忆，最多 4000 字符、1600 个估算 token；超预算条目
整条跳过。记录本次使用的 ID 和修订号，不另外复制记忆正文。
查询本地编码最多等待 3 秒，不可用时回退关键词。自动提取依赖本地编码器，
编码器不可用时任务失败，不会静默调用云端向量接口。修改内容后旧向量失效。
模型变化需要重建索引；原来的有效记忆向量可以继续使用。

沿用当前资源上限：每条正文 1200 字符、每项目 100 条、每账号 500 条；
每账号滚动 24 小时最多 20 个提取任务，排队或运行最多 10 个。提取调用最多
40 秒和 3000 输出 token；含 SDK 较长的提取规则，单次总用量设置 32000 token
上限（供应商实际用量返回后检查，并非预付费硬限额）。整个 SDK 阶段最多等待 55 秒。超时后原生线程仍在
运行时保留繁忙槽，避免不断堆积线程。失败可重试一次，总尝试不超过两次。
配额达到时停止新增，页面展示近期任务状态和用量；不会自动删除旧记忆腾空间。

本功能与会话上下文分层：原始消息和 LangGraph checkpoint 仍持久保存在 PostgreSQL。
会话内的话题检索、来源关联滚动索引和近期消息预算见 [长会话上下文](conversation-context.md)，
不会自动写入本功能的长期记忆。长期任务工作状态和自主遗忘策略仍需继续建设。
记忆不能代替知识库原文引文，也不能授予工具权限或覆盖系统指令。

## 升级与验证

迁移 `0045_mem0_memory` 在 `0044_conversation_generation` 后执行：

- 保留已有事实、ID、来源、向量和版本；增加自动/手动来源及原文摘录字段。
- 保留总开关状态，已开启记忆的项目启用自动整理；取消旧执行中的提取任务。
- 旧待确认候选标记为已替代，不直接提升为有效事实；正常保留到清理期限。
- Downgrade 停止自动提取并删除本次新增的来源标记字段；不删除记忆正文或版本。
  发布前仍需备份数据库。

验证使用真实 Mem0 SDK、模拟生成模型/编码器，以及独立 `_review` PostgreSQL
数据库，覆盖自动写入、纠错、去重、作用域、来源清理、并发、关闭/删除期间
的任务失效、旧消息迟到、过期和关键词回退。前端验证自动记忆界面与原文入口。
这些测试不代表生产模型的事实提取准确率；正式效果还需用中文真实对话评估。
