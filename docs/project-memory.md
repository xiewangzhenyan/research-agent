# 项目记忆

项目记忆保存用户确认的重要结论、约束、偏好和笔记，供同一项目的新聊天
按需回忆。入口为侧栏或项目菜单中的“项目记忆”，也可在已保存的聊天消息
下点击记忆图标，整理内容后确认保存。默认关闭，各项目单独开启。

## 数据边界

- 知识库仍属于账号，所有项目可复用；记忆按 **账号 + 项目** 隔离。
- `X-Project-ID` 选择当前项目，省略只代表默认项目。后端验证项目所有权，
  编辑、删除、来源查询、设置和召回全部应用同一边界。
- WebSocket 使用连接建立时验证的项目，每轮读取最新记忆开关及笔记。
  不信任消息体传入的项目 ID，不把其他会话历史自动拼进新会话。
- 来源消息必须属于该账号和项目。由消息整理的记忆可以改写，不能冒充
  原文引文。删除来源会话/消息会级联删除关联记忆；手动笔记独立保存。
- 关闭或删除记忆影响后续召回，不能撤回已发送给模型的内容，也不会擦除
  历史回答中已出现的内容。若需清除会话历史，应单独删除会话。

## 召回与上下文

当前采用中文双字词及英文词的关键词匹配，置顶条目优先。每轮最多载入
6 条完整记忆，记忆上下文块最多 4000 字符、1600 个估算 token。
估算考虑中文字符，但不是模型供应商 tokenizer 的精确计数。超预算的
条目整条跳过，避免截断否定、数值或条件；界面可预览本次召回内容。

记忆是补充参考，不能授权工具执行、覆盖当前请求或充当知识库 `[1]` 引用。
严格知识库问答完全排除记忆；普通聊天独立展示使用的记忆条数。历史回答
保存条目 ID 和修订号，不复制笔记正文；用户可以查看当前版本，修改或
删除后的差异有提示。记忆内容发生冲突时提示模型说明冲突或请求澄清。

这是用户确认的长期笔记与聊天召回，**没有自动记忆提取、语义记忆检索、
全会话摘要压缩、跨项目召回或后台任务记忆**。不依赖 Neo4j，不新增模型
服务。短期对话窗口和任务 checkpoint 仍由现有聊天/任务模块管理。

## 写入与运维

每条正文上限 1200 字符、标题上限 80 字符，每项目 100 条、每账号 500 条。
同项目规范化空白后的重复内容拒绝保存。写入通过账号行锁串行校验配额，
设置、编辑和删除携带 revision，过期修改返回 409，不覆盖较新版本。
并发来源删除由外键确保不留下悬空记录。

迁移 `0041_project_memory` 新增两张 PostgreSQL 表，NULL 项目唯一约束
保留默认空间边界；复合外键绑定账号与项目。无需搬迁既有文档或会话，
部署前备份数据库。回退应用可保留新增表；降级数据库会删除记忆数据。

验证：`tests/test_memory.py`、`tests/test_memory_integration.py`，以及前端
memory 组件与代理测试。数据库测试仅在 `_review` 结尾的临时数据库启用
`RUN_TASK_DB_TESTS=1`，先执行迁移和任务 checkpoint setup。
