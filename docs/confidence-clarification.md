# 信息完整性检查与持久化澄清

实现版本：`clarification-v1`。本轮为本地开发，尚未推送或发布。

## 用户行为

- 日常概念问答走直接路径。涉及任务目标、计算、文件、知识库、指代或分析执行的请求，先做结构化的信息完整性检查。
- 缺少会改变结果的输入、对象存在歧义或要求冲突时，显示原因、最多三个问题，每个问题最多三个选项；也可填写具体信息或取消本轮。
- 必要问题不能跳过。服务器根据保存的问题校验回复，拒绝空答案、跳过标记、常见无实质内容的回复及闭合选项以外的值。自由填写仍可能不充分，因此回复后再次检查。
- 格式、篇幅、语气等偏好默认自行选择并要求回答说明假设。模型在执行中显式提出的可选偏好仍允许采用默认值。
- 严格资料回答缺少有效引用时，按原始问题回退补检索一次；仍不足则暂停，允许补充检索线索、重新检索或结束。本轮最多接受一次此类重试。原始问题与初次查询相同时，补检索可能得到相同结果，不能保证改善召回。
- 资料协作已有检索和一次审校修订，审校仍不通过时进入澄清。重试再次经过完整协作和审校；预算不足则直接说明原因并停止。

## 暂停与恢复

新聊天提交时在服务端固定策略版本。LangGraph 执行链为：

```text
准备会话上下文 → 检查必要信息 → 自动路由 → 检索／生成／协作 → 校验证据
                       ↓                         ↓
                 持久化问题                  证据不足问题
                       ↓                         ↓
                   interrupt ← 用户补充 → interrupt 恢复
```

`waiting_input` 不占用模型或沙箱执行；PostgreSQL 保存 run、问题、事件及 graph checkpoint。关闭网页不丢失问题，重新打开原会话可继续。后台已有七天等待清理规则继续适用。

同一模型响应同时提出澄清和执行工具时，`ClarificationFirstGuard` 仅保留第一个 `ask_user` 调用，在派发工具前拦截同批其他调用。用户回答后，模型可重新请求获授权的工具。已在更早调用中执行完成的操作不会被事后自动撤销。

最多三次必要信息检查；仍有缺口时结束本轮并列出未解决问题。普通模型内澄清还受五轮生成上限、新策略 18 次累积模型请求（旧任务仍为 12 次）、20 次工具调用、60,000 token 和 worker 单次 300 秒限制。资料协作与检查共享累计 usage；路由、问题改写和严格资料生成目前仍各自有调用／超时边界，并非全部计入同一个 token 计数器。

检查器单次超时 45 秒，无工具权限；仅当部署策略允许推理强度控制时，内部检查固定使用低档，不继承长回答的推理预算。普通回答仍遵循用户设置。检查输入包含已绑定的能力类型；工具内部文件、接口定义和执行后才产生的结果交由助手按需获取，不要求用户提前提供。不可用时停止后续执行并提示重试。基本问答不额外调用检查模型；复杂请求增加一轮调用，实际耗时取决于配置模型。

## 会话、来源及权限

- 账号、项目、run 所属关系和当前任务修订在恢复前重新验证。补充信息不能扩大知识库或工具授权范围。
- 每轮问题 ID 包含轮次；旧问题不能恢复新一轮。相同请求重复提交不会重复记录事件和消息。
- 接受的问答在同一事务中写入审计事件及一条用户会话消息，后续上下文检索可以读取。消息在原 turn 内排序；事件时间记录实际提交时刻。原始目标消息及其内容哈希不变。
- 新增补充消息也加入来源校验。恢复时及后续模型调用／结果保存前发现删除或修改，停止使用旧内容。
- 用户回复只作为输入或搜索线索，不能成为知识库引用。已有严格引用校验仍要求真实来源、原文片段和数字支持；引用展示仍通过受授权的引用接口加载。
- 已排队／运行但未保存新策略的旧任务保持原来的初始执行路径。旧问题未声明 `required` 时按兼容语义处理。
- 澄清记录属于当前会话历史；不会在此机制中自动升级为跨项目长期记忆，也不修改 Mem0 后端。

## 前端

中文问题、原因及按钮；必答问题隐藏跳过入口。用户可以取消当前等待的那一轮、返回修改前一题；提交失败保留输入，重试不增加答案数量。输入兼容中文输入法组合态。卡片高度受视口约束、内部滚动，选择项可换行。切换会话后忽略旧请求的提示和刷新。

## 验证与能力边界

- `backend/tests/test_clarification.py`：问题协议、跳过校验、混合工具拦截、结构化模型协议、偏好默认及检查器故障。
- `backend/tests/test_clarification_integration.py`：独立 PostgreSQL 下暂停恢复、隔离、幂等、重新检查、轮数上限、目标修订／取消、文档工具拦截、证据重试、协作审校、来源删除及后续会话上下文。
- `frontend/src/components/ui/question-prompt.test.tsx`：必答／可选交互、返回编辑、草稿、重试及输入法。
- `frontend/e2e/durable-chat.spec.ts`：桌面与手机浏览器下恢复问题、校验失败重试、取消与历史恢复。

这里的“置信度”是执行是否具备必要输入和证据的判断，不是经校准的答案正确率。触发规则和模型语义判断可能漏检或误判；已有引用检查也不是逻辑蕴含证明。当前测试使用离线模型，验证流程和安全边界，没有宣称真实模型的识别准确率或完成率。后续可用匿名化真实案例评估误追问率、漏追问率和补充后的完成率。

本地验证记录（2026-09-14）：后端单元测试 557 项通过，覆盖率门槛通过；受影响数据库回归 51 项通过、1 项可选本地向量模型测试跳过；前端单元测试 145 项通过、覆盖率门槛通过；聊天与任务的桌面／手机浏览器回归 22 项通过。Ruff、后端类型检查、前端类型检查及本地生产模式构建通过。现有依赖弃用提示及项目存量警告仍存在。数据库使用独立容器；未调用付费模型，未修改生产数据库。
