# 长会话上下文与话题恢复

会话原文、会话历史索引和 Mem0 项目记忆是不同层次。原文持续保存在 PostgreSQL，
本功能只为同一个账号、项目、会话提供检索与上下文组装，不会将每段讨论自动提升为
跨会话的个人事实。项目记忆的自动抽取和纠错仍由 Mem0 管线负责，遵循其总开关。
本功能随普通聊天自动工作，不需要选择话题、确认摘要或进入另一个任务页面。

## 每轮如何组织上下文

1. 校验会话归属，以及用户消息的 ID、角色和原文是否与已保存的请求相符。
2. 保留最多 12 条近期完整消息，按模型预算缩减；不读取未完成的 assistant 回答、
   system 消息、隐藏思考或工具执行指令。不会读取当前用户消息之后的历史。
3. 用当前问题在当前会话的旧索引中搜索。只有明确的简短续问才补入最近用户问题，
   明确的新话题不会自动拼入其他话题。中文词项与本地 BGE 向量候选用 RRF 合并。
4. 回到原始消息核对摘要来源哈希，取出最多 6 段相关原文，每段最多 1400 字符。
   长消息展示明确的节选标志；恢复的内容是历史参考，以当前要求为准。
5. 严格知识库问答仅使用历史用户问题帮助检索改写，历史 assistant 回答不能成为证据。
   `[1]` 等证据编号始终属于知识库引用。

例如，先讨论做饭，再讨论数学和经济，最后问“回到做饭，之前有哪些限制”，
系统能按相关性取回旧的菜谱要求，而不必把所有聊天重新塞入模型。
这属于检索能力，不保证任何含糊的“之前那个”都能识别正确话题；无法确定关键约束时，
助手仍应说明不确定性或澄清。不同游戏、项目或任务也不会仅因属于同一领域就合并为一个任务。

回答下方的“已衔接 N 段历史”按需读取本次使用的原文，标明用户/助手与是否节选。
访问需要重新校验账号、项目、会话和回答。原文删除或修改后显示失效状态。
前端切换账号、项目或会话时清空展开内容并取消请求，不把历史原文存进浏览器持久缓存。

## 后台滚动索引

- 每批 8 条可用消息生成结构化主题、约束、决定、进度或问题索引，不递归覆盖一个全局摘要。
  每条摘要必须附有输入中的逐字摘录和来源序号；未通过来源检查的内容不会进入摘要索引。
- 每条历史消息截取前 1500 字符进入摘要与向量索引，明确标记省略。原始完整消息不变。
  逐条消息的原文与同源摘要组成各自的检索索引，摘要标签也参与关键词匹配；
  向量按消息单独生成，避免跨话题求平均后稀释主题。本地编码器为现有 BGE，512 维，
  与 pgvector 一起使用，不下载新模型、不调用云端向量 API。
- 模型一次调用最多 25 秒、2200 输出 token，按账号滚动 24 小时最多 40 个生成式摘要批次。
  超额或模型失败时仍生成逐字摘录索引；不阻塞聊天，不反复重试生成模型。
  崩溃恢复累计两次后也改用摘录。失败调用同样计入已完成批次的生成尝试统计；
  进程在持久写入前崩溃的尝试不在该日用量中，因此这不是供应商计费硬限额。
- 向量不可用时保留关键词索引。查询本地编码最多等 3 秒，忙碌或异常则回退关键词。
  当前语义候选阈值为余弦相似度大于 0.44，这是可调整的启发式，未经生产语料标定。
- 首次访问旧会话或新回答完成后自动排队补建。未建索引的尾部可搜索最近 200 条较早消息
  的前 20000 字符。历史更久、长消息后半段和模糊指代可能暂时找不到，不能据此声称原文丢失。
- 队列与游标在 PostgreSQL。独立轻量循环和现有任务、记忆 worker 并行运行；
  账号 advisory lock 避免多副本重复构建与配额竞争；模型调用期间不持有行锁事务。
  活跃的旧任务会阻止索引越过其消息边界，避免后来完成的回答被游标遗漏。

数据库 `0046_conversation_context` 增加 jobs、blocks、sources 表及索引。
原文内容、角色、会话或排序时间修改/删除时，数据库触发器清除该会话的衍生索引并重置游标。
最终写入锁定源消息并校验哈希、游标、revision、attempt、账号和项目，使迟到结果不能覆盖新版本。
删除账号/会话级联清理索引。迁移及降级均不删除原始聊天记录。

LangGraph 仍以 PostgreSQL checkpoint 恢复执行；本次没有改成 Redis checkpoint。
恢复生成以及普通工具循环的每次模型请求前重新校验历史来源，变更后停止该旧任务并提示重新发送。
升级前已 checkpoint 的旧上下文没有来源校验信息时也要求重新发送。已经生成完成的回答正文
不会因为源消息变更而自动重写，也不会从已有任务 checkpoint 中自动擦除；原文展开与后续使用会失效。
checkpoint 保留与清理沿用任务服务的规则。

## 上下文预算

`AI_MODEL_CONTEXT_LIMITS` 接受模型 ID 到窗口 token 数的 JSON 映射，例如：

```dotenv
AI_MODEL_CONTEXT_LIMITS={"your-model-id":65536}
```

未配置的模型保守按 32768 计算，允许窗口范围 8192–262144。每轮原始材料预算最多
24000 token，先预留实际输出上限和 4096 系统/工具预算，再分配当前问题、知识资料、附件、
项目记忆、近期消息与历史参考。使用中文敏感的字符估算，不是供应商精确 tokenizer。
图片暂按每张 2000 token 估算，具体模型的图片分辨率计费仍可能有差异。

当前问题和用户选择的输出上限不被静默截断。知识资料按完整片段取舍，记忆按完整条目取舍。
附件超过本轮预算时提示拆分或导入知识库，不悄悄只读取附件开头。
PydanticAI 请求钩子在每次普通 Agent 模型调用前核对消息、工具定义与工具结果，
过大时结束当前任务并提示拆分。严格知识回答也有请求预算检查；协作流程仍有自身的
角色、调用次数和用量边界，尚未统一成跨所有角色共享的精确 token 调度器。

回答配置记录近期消息数、历史来源 ID/哈希/节选位置、检索方式、估算输入量、预留输出
和省略标志。它不复制原文或摘要正文。估算输入量是组装阶段的观测值，不包含整场多轮工具调用的总用量。

## 验证与边界

测试使用独立 `_review` PostgreSQL，覆盖 A→B→C→A、项目/账号/会话隔离、原文失效、
模型执行期间编辑、补建游标、未完成和未来消息排除、严格问答边界、预算，以及前端请求取消。
本地 BGE 与 pgvector 做真实链路验收；云端摘要/回答模型以可控响应替代，
这些结果不能当作生产模型的摘要准确率或话题召回率。生产中文语料评估、跨角色预算调度、
更长消息的分段索引与长期任务工作状态仍需后续建设。
