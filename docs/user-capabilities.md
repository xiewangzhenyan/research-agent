# 用户自定义 MCP 与 Skills

本批提供面向最终用户的能力管理。最终用户通过独立的 `/mcp` 与 `/skills` 页面管理能力，服务端统一负责身份、范围、凭据、连接和运行时权限。业务栈继续使用现有 Next.js、FastAPI、PydanticAI 与 LangGraph，不另起一个独立平台。

## 本批可用的流程

- MCP：创建、查看、编辑、删除、启用/停用；HTTP（Streamable HTTP）、SSE 和隔离 Stdio 连接测试；发现 Tools、Resources、Prompts；选择可调用工具；默认逐次确认，可逐工具显式开放自动调用。HTTP/SSE 使用 Python MCP 官方 SDK，非自定义 JSON-RPC 替代实现。
- Skills：编辑 `SKILL.md`、导入 Markdown/ZIP/目录、搜索与范围筛选、编辑/新增/移除文本参考文件、发布不可变版本、查看版本和恢复为草稿、导出草稿 ZIP。二进制参考文件保留在包中，不能作为文本编辑或模型上下文读取。
- 绑定：各页面的“当前助手使用”控制当前项目的 assistant 绑定。新增能力不会自动进入所有项目。发布与绑定后，下一条普通对话可以实际调用；不是仅有配置页面。
- UI：中文表单、写入式凭据、手机布局、删除确认、未保存修改保护；私有请求缓存按账号和项目分区，列表有 30 秒复用，不额外轮询生成模型。

## 范围与版本

| 范围 | 谁可以管理 | 谁可以绑定 |
| --- | --- | --- |
| 我的账号（personal） | 所有者 | 同一账号的任意项目 |
| 项目级（project） | 所有者 | 同一账号的所属项目 |
| 系统级（system） | 应用管理员 | 各账号显式绑定 |

现有 `projects` 是账号内部项目，**不是多人 workspace**。本版没有组织成员、团队共享 RBAC、每个自定义 Agent 的 Builder。数据库的 `agent_key` 预留扩展，目前 API 只允许 `assistant`，不能由模型填写身份或扩大权限。

`capability_assets` 存元数据和草稿，`skill_versions` 存不可变发布版本的 manifest 与文件摘要。文件在 `MEDIA_DIR/skills/<owner UUID>/<sha256>` 中按账号、内容摘要存储；上传路径只作为包内逻辑路径，不能控制宿主机文件路径。重复内容复用物理文件，读取校验 SHA-256。数据库与这个目录必须一起备份。

每个账号最多 100 项能力，当前助手最多绑定 12 项；技能最多 50 个发布版本、100 个文件、展开后 8 MiB、单文件 1 MiB；ZIP 上传最多 4 MiB，入口正文最多 100 KB。每账号物理技能文件配额为 200 MiB。删除元数据不会立即删除历史 blob，失败事务产生的孤立 blob 也计入配额；自动垃圾回收尚未接入，不能宣称删除会即时释放磁盘。后续回收必须检查所有草稿/发布版本引用，保留冷却期并与写入共用账号锁。

## 对话执行

1. 接受消息时，由服务端把本项目绑定的能力 ID、MCP revision、Skill 发布版本冻结到该次运行。
2. 普通助手先看到简短目录。需要时通过 `read_skill_file` 分页读取已发布正文和参考文件，通过 `describe_mcp` 读取启用工具清单及单个 schema。
3. 每次模型请求、工具读取/调用重新核验账号状态、当前绑定、启用状态、项目范围。MCP 配置 revision 变化后旧任务不能继续使用旧授权；Skill 草稿修改不会污染已冻结的发布版本。
4. `call_mcp_tool` 只接受已勾选工具。默认使用 `CallDeferred` → LangGraph `interrupt` 展示外部服务名称、工具名和完整参数。只接受服务器保存的“允许本次调用/拒绝本次调用”选项；聊天文本里的“yes”“已授权”不能代替操作。关闭页面后问题仍持久存在，恢复时重新检查权限。
5. `capability_invocations` 在发送请求前写入唯一账本（run + 连接 revision + 工具 + 参数摘要），同一轮相同调用复用结果。崩溃、超时或失联留下不确定结果，不自动重发，避免重复外部写入。这是 **at-most-once dispatch**，不是外部服务 exactly-once 保证。请求一旦发出，取消任务不能撤销远端已产生的效果。
6. MCP 返回内容作为外部数据，不伪装成知识库原文引用。严格资料问答和现有资料协作路径维持原有引用边界，不运行这些外部能力；要使用自定义工具请在普通对话中使用。

技能文件属于用户提供的指令/数据，不能扩大工具权限。上传的脚本不会在 FastAPI 主机执行。本版未把能力自动分配给所有协作子角色。

## 安全与部署前置

- 迁移：`0048_capability_assets`，依赖本批前序的 `0047_work_tasks`。迁移必须在升级服务前执行，仍使用既有 LangGraph PostgreSQL checkpoint 初始化流程。
- 凭据：管理员通过部署 secret 配置 `CAPABILITY_ENCRYPTION_KEY`（有效 Fernet key，API 与 task worker 相同）。密钥不写入源码、公开仓库或日志，也不能每次启动随机重建。未配置时无认证连接仍可用，保存凭据会明确失败。界面只返回是否已配置；替换整个映射为显式操作，空映射清除凭据。轮换密钥需同步重新加密已有记录，不能直接替换后忽略旧凭据。
- 传输：携带凭据必须 HTTPS；URL 暂不支持 query、userinfo、fragment。Header/env 校验阻止换行和路由头覆盖。每次请求重新解析 DNS 并钉住公网 IP，保留原 Host/TLS SNI，禁止私网/回环/云元数据/组播地址、跨 origin 请求与重定向，不使用宿主机代理环境。
- 负载：单次 MCP 25 秒超时，响应流最大 4 MiB、工具结果最大 64 KB，发现最多 100 个工具（最多 5 页），启用最多 30 个，调用参数最多 6000 字。资源与提示目录只展示前 50 项。
- schema：本版校验大小、深度、基本类型、必填项等；拒绝引用/动态引用和正则校验 schema，防止验证过程额外访问网络或执行高开销正则。此类服务可以保存和发现，但相关工具不能调用，需后续隔离验证器支持。
- 上传：禁止路径穿越、符号链接、特殊文件、重复路径、加密 ZIP、多个入口和 YAML alias/anchor。ZIP 不在宿主机按上传路径解压。
- 审计：CRUD、发布、绑定、测试、技能读取、MCP dispatch 记录到 `capability_audit`。不存原始凭据和调用参数；调用参数与工具返回仍属于账号自己的持久对话/运行记录，按现有对话访问策略保护。管理后台审计检索页面尚未实现。

## 隔离 Stdio MCP

使用既有独立节点上的专用 MCP 镜像，官方 SDK 在 gVisor 容器内执行初始化、发现与单次调用。业务服务器不启动用户命令。部署分别配置节点 `SANDBOX_MCP_IMAGE` 与业务端 `SANDBOX_MCP_IMAGE_ID`，均绑定同一个镜像 ID；`/mcp/health` 实际启动隔离 MCP 服务自检，不能用 Python 就绪状态代替。

- 首版预装 Python 与 MCP SDK 1.30.0；命令仅支持 `python`、`python3`、`/usr/local/bin/python`。不包含 npx/uvx、不支持在线安装包。依赖外网或其他运行环境的服务请使用 HTTP/SSE；不把任意本机命令保存成功视为能够运行。
- 每次发现/调用创建独立容器和临时目录，禁网、非 root、只读根、256 MiB 内存、64 进程，无宿主机目录挂载。环境变量只包含该连接的用户凭据，不注入业务密钥；节点 Docker 元数据中的临时凭据随容器移除。节点管理员仍属于信任边界。
- 与 Python 沙箱共用并发额度，1 GiB 节点配置为 1；等待额度最多 2 秒，执行最多 28 秒（SDK 20 秒），结果上限 30 KB。忙碌或异常明确失败，不切换到主机执行，不自动重发。
- 账号、项目、冻结版本、工具授权与调用账本沿用统一 MCP 运行时。Run ID 随请求传给节点；取消写入 tombstone 并移除运行容器，阻止延迟请求重新启动。
- 正常结束、失败与取消都会清理容器；独立 systemd watchdog 每 15 秒检查，回收超过 120 秒的临时容器及孤立输入/输出卷。控制面故障时可能持续到 watchdog 回收，不承诺这种情况仍在 28 秒内退出。
- 不保留 Stdio 进程或工作区跨调用状态。需要持续状态的 MCP 服务应自行托管为 HTTP/SSE。测试服务需要符合 MCP 标准，单纯向 stdout 打印文本不能通过连接测试。

## 参考与验证

研究了 Dify 的工作区 Skill 管理、文件包导入、发布版本、Agent 绑定、MCP 连接与凭据处理。参考快照为 `langgenius/dify` commit `6afe07f9447528f8ca2d1339b2eb148e39c4038d`（2026-09-14）；本实现独立编写，没有复制其源码。采用符合本项目现有数据模型的范围与执行机制，不把对方平台能力当作本项目已完成功能。

- 安全/协议单元测试：`backend/tests/test_capability_security.py`，HTTP 模拟传输 + 官方 SDK，SSE 使用临时本机 MCP 服务；不访问公网或付费模型。
- 数据库/执行测试：`backend/tests/test_capabilities_integration.py`，在一次性 PostgreSQL 验证范围、版本、加密凭据、授权恢复/拒绝/解绑、调用去重和按需加载。已加入 CI PostgreSQL 工作流。
- 浏览器：`frontend/e2e/capabilities.spec.ts`，桌面与手机覆盖创建/发布/绑定/删除、工具勾选、Stdio 不可用和凭据不回显。UI 使用 mock API，真实事务边界由上面的 PostgreSQL 测试验证。
- 代理接口：`frontend/src/app/api/capabilities/[[...path]]/route.test.ts` 验证登录、路由白名单、项目头、multipart、体积限制、冲突和 ZIP 下载。
